# Git-Commit-RewriterGUI

Git-Commit-RewriterGUI 是一个基于 Qt 6 Widgets 的本地 Git 历史查看与改写工具。它通过 Git 原生命令读取和重建提交对象，不依赖其他模块。

软件默认使用“生成安全副本”模式，让用户先在独立仓库中检查改写结果；如确需直接修改当前仓库，也可以在创建 `.bundle` 恢复备份后执行。

## 功能概览

### 浏览仓库历史

- 选择仓库或仓库内的任意子目录，并自动向上查找最近的 `.git`；
- 列出本地分支，显示提交总数、独立作者数和本地分支数；
- 每次分页加载最多 1000 条提交，展示哈希、说明、作者、邮箱、时间和提交者详情；
- 在已加载的提交中按哈希、说明、作者或邮箱进行大小写不敏感过滤；
- 汇总已加载提交中的作者身份和提交数，继续加载后自动更新统计。

搜索和作者汇总只基于当前已经加载到界面的提交。批量改写前的影响分析会独立扫描所选分支的完整历史，不受分页状态影响。

### 修改单条提交

选中提交后，可以同时修改：

- 完整提交说明；
- 作者（author）的姓名和邮箱；
- 提交者（committer）的姓名和邮箱。

目标提交发生变化后，从该提交到分支顶端的后续提交会因为父提交哈希变化而被依次重建。单条改写只更新所选本地分支；原地模式要求该分支正处于检出状态。

### 批量修改身份

- 从作者汇总中选择身份时，原姓名和邮箱会自动带入批量窗口；
- 按“姓名 + 邮箱”完整、区分大小写地匹配旧身份；
- 默认同时修改作者和提交者，也可以只修改其中一种身份字段；
- 从本地分支列表中勾选改写范围，支持全选和清空；
- 当前分支默认勾选；
- 执行前必须完成影响分析，界面会显示作者命中数、提交者命中数、去重提交数和逐分支统计；
- 分析后会记录分支顶端，若执行前分支历史发生变化，程序会要求重新分析；
- 共享提交只重建一次，选中分支通过一次引用事务统一更新。

## 两种改写模式

| 模式 | 对源仓库的影响 | 输出范围 |
| --- | --- | --- |
| 生成安全副本（默认） | 不修改源仓库 | 单条改写生成仅包含目标分支的副本；批量改写生成保留全部本地分支的副本，但只更新勾选分支 |
| 直接修改当前仓库 | 创建外部 `.bundle` 后更新本地分支 | 单条改写更新当前检出分支；批量改写更新所有勾选的本地分支 |

两种模式都不会自动修改远端仓库，也不会自动推送。

## 基本使用流程

1. 启动程序并选择 Git 仓库。
2. 选择本地分支，按需加载更多提交。
3. 修改单条提交时，在提交列表中选择目标记录并点击“修改此提交身份”。
4. 批量修改时，可先在右侧作者汇总中选择身份，再点击“使用选中作者创建批量方案”。
5. 保持默认的安全副本模式，或明确选择原地修改模式。
6. 批量修改需要先点击“分析影响”，确认范围后才能执行。
7. 完成后检查新提交哈希、身份、提交说明以及分支历史，再决定是否处理远端分支。

## 安全边界

历史改写会改变目标提交以及受影响后续提交的哈希。程序具有以下保护：

- 安全副本目录必须位于源仓库外部，且执行前不能已经存在；
- 原地备份必须是仓库外部、执行前不存在的 `.bundle` 文件；
- 原地改写会拒绝暂存区相对 `HEAD` 存在的任何已 `git add` 变更；
- 未暂存的已跟踪文件修改和未跟踪文件不会阻止执行，也不会被 `.bundle` 备份；
- 原地改写会拒绝尚未完成的 merge、rebase、cherry-pick、revert、bisect 或 sequencer 操作；
- 单条原地改写只允许操作当前检出的分支；
- 批量执行前会确认所选分支与影响分析时的顶端一致；
- 标签和远程跟踪分支不会被改写；
- 重建提交时会移除已经失效的 GPG/SSH 提交签名及合并标签签名；
- 引用更新完成后，程序会重新读取历史并验证目标内容或身份替换结果。

`.bundle` 只保存 Git 对象和引用，不包含工作区文件。即使程序允许保留未暂存修改和未跟踪文件，也应自行备份其中的重要内容。

如果被改写分支已经推送到远端，后续通常需要人工检查并谨慎执行强制推送。程序不会代替用户完成该操作。

## 运行与构建要求

- Git 可执行文件必须位于 `PATH`；
- Qt 6.11 或更高版本，包含 Widgets 组件；
- CMake 3.21 或更高版本；
- 支持 C++20 的编译器。

仓库中的预设面向当前 Windows 开发环境：Qt 6.11.1、MinGW 13.1 和 Ninja。若 Qt 安装位置不同，需要调整 [CMakePresets.json](CMakePresets.json) 中的路径。

在 `guiProject` 目录构建 Debug 版本：

```powershell
cmake --preset qt6-mingw-debug
cmake --build --preset build-debug
```

构建 Release 版本：

```powershell
cmake --preset qt6-mingw-release
cmake --build --preset build-release
```

Debug 可执行文件位于：

```text
build/qt6-mingw-debug/Git-Commit-RewriterGUI.exe
```

也可以使用 Qt Creator 直接打开 `CMakeLists.txt`。

## 从 bundle 检查历史

建议将备份克隆到新的目录，不要直接覆盖当前仓库：

```powershell
git clone "<backup-file>.bundle" "<restored-directory>"
```
